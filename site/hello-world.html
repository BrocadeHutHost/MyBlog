为什么要写博客

把日常开发里踩过的坑、验证过的方案写下来，是最省事的复习方式：写的时候逼自己把话说清楚，回头读的时候又能一眼想起当初为什么那样做。

所以这里的定位很明确——偏工程、可落地，少谈概念，多给能跑起来的代码。

第一行代码

按惯例，第一个程序总要打印一句话。这篇《Hello World》本身，就是这个博客的第一行。

csharpConsole.WriteLine("Hello, World!");

这个站是怎么搭起来的

结论先说：没有构建步骤。就是手写的 HTML 加一个 CSS，再配一点点 JavaScript，推到 GitHub 上就是网站了。

为什么不用框架

个人博客最需要的其实是「十年后还能打开」：静态文件打开就能看，不需要装 SDK，不需要跑编译，也不会因为某个运行时升级而白屏。改内容就是改 HTML，加文章就是加文件。

怎么发布

源码放在 GitHub 仓库里，推送到 main 分支后由 GitHub Actions 自动把 site/ 目录发布到 GitHub Pages，不需要自己买服务器。

  • 页面：每个栏目一个 HTML，全站共用一个 CSS。
  • 目录：左侧目录由几行 JS 从正文的 h2 / h3 生成，写文章时不用管它。
  • 清单：文章列表、分类、标签都从 assets/posts.js 里读，加一条就自动出现在各处。

接下来写什么

先把结构立住：顶栏分栏目，每页左侧一个两级目录，和参考的站保持一致。之后按主题慢慢补文章。

  • 桌面开发：WPF 与 Avalonia 的控件、样式和迁移。
  • 跨平台：多端工程的拆分与共享代码的组织方式。
  • 部署与性能：构建流水线、静态站点与体积优化。
