这学期把手上散装的各种优学院脚本整理了一遍，融合成一个聚合脚本——「理工小助手」。
学习功能面向东莞理工学院的优学院平台，工具箱部分则是任何网页都能用的本地小工具。
这篇随笔讲讲它为什么存在、能做什么、去哪下载。

项目地址：[BrocadeHutHost/DGUT-ULearningTakeQuizzesAssistant](https://github.com/BrocadeHutHost/DGUT-ULearningTakeQuizzesAssistant)

## 为什么写这个脚本

签到、刷课、互评汇总、读书计时……优学院的这些辅助功能，原本大多由不同的作者各自发布。
单独看每个都能用，凑到一起就很折磨：

- 油猴列表里躺着一长串脚本，谁对应哪个功能要对半天；
- 各作者的更新节奏不同，有的已经弃坑，功能却还在用；
- 每个脚本一套面板、一套操作逻辑，界面风格五花八门；
- 同时启用容易互相干扰，出了问题都不知道该找谁。

要管理多个脚本和维护实在是太不方便，于是干脆自己动手写了个融合版：
所有功能收进一个脚本，统一入口、统一设置、统一更新，维护成本一下子就下来了。

## 它能做什么

### 学习功能

| 模块 | 能做什么 | 状态 |
| --- | --- | --- |
| 课程签到 | 读取课程列表，按间隔轮询当日课堂活动，发现签到自动提交 | 排查修复中 |
| 刷课助手 | 视频 1~16 倍速播放、倍速守卫、自动答题、自动翻页、题库收集与导出 | 正常 |
| 作业互评 | 读取互评数据、还原评价人身份、汇总记录并筛选 | 正常 |
| 求是读书 | 按书目累计阅读时长，满 4 小时 10 分自动翻页、切书 | 正常 |

几个设计上比较谨慎的地方：

- **自动答题绝不盲点**。答案按「页面视图模型 → 本地题库 → 答案接口」的顺序取，
  取不到就不作答，未知题型一律跳过——平台测验大多限答一次，瞎点的代价太大。
- **倍速守卫**。平台把倍速改回去时脚本会立刻改回设定值，
  还会学习平台的重置频率来调整检查间隔。
- **互评去匿名**。在互评详情页还原评价人的姓名与班级，
  记录支持按 `80-95`、`>90` 这类写法筛选分数区间。
- **签到的身份校验**。用户 ID 从多个来源解析并标注置信度，
  低置信度时直接拒绝自动签到，宁可不做也不误用他人身份。

> 二维码签到只处理活动数据里自带签到码的情况，
> 脚本不会去识别教室大屏幕上的二维码图片，其余情况会明确跳过并记录原因。

### 本地工具箱

这一半和学习平台无关，任何网页点开右下角的悬浮球都能用：

| 工具 | 能做什么 |
| --- | --- |
| 文档工具 | Markdown 转 Word / PDF，支持实时预览、草稿自动保存 |
| Word 转 PDF | 本地解析 .docx，导出 PDF / .doc（复杂排版还原度有限，持续优化中） |
| 图片工具 | 缩放、压缩到指定大小、增大文件、锐化、黑白、亮度均匀 |
| 手绘电子签名 | 画板上手写（鼠标 / 触屏 / 触控笔），可存多份，导出时以透明 PNG 附在文档末尾 |

两个顺带一提：

- 「下载 PDF」本地直出，不用再跳打印对话框；对清晰度要求高就选「打印 PDF」，
  文字是矢量的，体积也小。
- 图片压缩做了「高质量平滑」——缩小时先逐级减半再插值，能明显减少毛糙和锯齿；
  像素运算在后台多线程跑，不卡界面。

## 其他细节

- **外观设置**：亮色 / 暗色 / 跟随系统，六种预设色外加自定义取色。
- **主题美化扩展（可选）**：纳西妲主题皮肤，纯外观增强；
  主脚本默认界面开箱即用，不装美化包完全不影响使用。
- **详情页**：版本信息、错误代码对照表、自检结果，
  还有个带 Star / Fork 数据和贡献者头像的 GitHub 项目卡片。
- **位置记忆**：面板可以拖动，位置自动记住；
  拖丢了在脚本菜单里一键重置即可。

## 隐私

文档内容、图片、签名全部在浏览器本地处理，不上传任何服务器；
配置、题库、签到和互评记录都存在本地存储里。做工具类功能，这条是底线。

## 下载与安装

1. 给浏览器装一个用户脚本管理器（Tampermonkey 等主流产品均可）；
2. 在管理器里新建脚本，把[仓库](https://github.com/BrocadeHutHost/DGUT-ULearningTakeQuizzesAssistant)里的主脚本完整代码粘贴进去；
3. 保存并保持启用；
4. 打开任意网页，右下角会出现悬浮球，点开就是面板。

想要主题皮肤的话，再去仓库下载 `小助手UI主题美化扩展-纳西妲主题.js`，
按相同步骤装上即可（前提：主脚本已装好并启用）。
首次使用文档相关功能需要联网加载依赖库，之后有缓存。

几个发布前要处理的地方：

- **图片**：把 README 里那三张截图下载下来，和 `index.md` 放同一个文件夹，命名为 `panel.png`、`docs.png`、`pdf.png`（如果你用了别的文件名，改 md 里对应三处即可）。图注里的文件名、大小、尺寸你的构建脚本会自动读取。
- **文件夹短名**：比如放到 `site/posts/dgut-helper/`，生成出来的页面就是 `site/dgut-helper.html`，名字随你定。
- **时效性内容**：签到「排查修复中」、Word 转 PDF「持续优化中」这类状态是照 README 当前情况写的，发布前记得和仓库最新状态对一下，博客里写死了容易过期。
